# hikizan：AIとの作業を把握し、選べるスキルパック

hikizanは、AIが進めた仕事を、人が理解して引き受けられる状態にするための、日本語の[Agent Skills](https://agentskills.io/)スキルパックです。「調べる・決める・作る・見る・出す・伝える」の6つの観点を、🌲の表示と短い選択肢で扱います。ルートの`plugin.json`は[Agent Plugins](https://agent-plugins.org/) v1に準拠しています。

各スキルは1つの`SKILL.md`で完結し、成果と人が関わる境界を定めます。実装や操作の手順は、モデルと利用先プロジェクトに任せます。

6つのスキルは固定工程ではありません。「PRまで」のように終点を指定すれば、必要な作業を進めます。通常の実装判断は任せられ、成果や保守負担を変える未決事項は推奨付きの`A（あ）` / `I（い）` / `U（う）`で選べます。英字とひらがなのどちらでも回答でき、明示済みの方針を形式的に確認し直しません。

## 使い方

やりたいことをそのまま依頼します。「設計だけ」「査読して」のように、関わりたいところを指定することもできます。

### 任せた範囲で完了する

以下は期待する会話の想定例です。モデルや利用環境での実測結果ではありません。

「保存エラーを直して」と頼み、既存の仕組みで修正できる場合：

> 🌲 jikkou（実行）：保存できない原因を確認して修正します。

修正と検証を行い、結果を返します。

> 保存に失敗すると入力内容が消えていたため、入力を残して再試行できるようにしました。失敗後の再試行まで確認済みです。

細かな実装方法の選択や、完了後の「終了」への返答は必要ありません。

### 引き受けるものが変わるときに選ぶ

「別の端末でもデータを使いたい」と頼み、端末内にしか保存していないことが分かった場合：

> 🌲 sekkei（設計）：端末間で使うための保存方法を整理します。
>
> サーバー保存なら別の端末でも同じデータを使えますが、認証とデータ管理が必要になります。端末間で日常的に使う目的にはこちらを勧めます。
>
> **A（あ）：サーバー保存に変更し、端末間で使えるようにする（推奨）**
>
> I（い）：端末内の保存を維持し、データを手動で受け渡す形にする

選ぶのは、使える機能と今後の運用の違いです。既にサーバー保存まで依頼されていれば、同じ確認は繰り返しません。

### 違和感を改善につなげる

「コメント多くない？」と聞かれ、今回の差分に説明の重複がある場合：

> 🌲 sadoku（査読）：追加した説明が、読む助けになっているか確認します。
>
> 処理をそのまま言い換えたコメントは削れます。外部サービスの制約を書いた箇所は、消すと実装理由が分からなくなるため残すのがよさそうです。

確認の依頼なので、この時点では変更しません。コメントを一律に減らす規則を増やす必要もありません。テストや依存の追加でも、成果に加え、その後に理解・管理する負担を考えます。

これらの例は、スキルごとの定型文や必須工程ではありません。使い心地は、説明や質問の数だけでなく、利用者が追加で読み解いたり軌道修正したりする仕事が減るかで確かめます。

## 導入

使用中の環境に合う方法を1つ選びます。

| 実行環境 | 導入方法 |
| --- | --- |
| Claude Code | Claude Codeプラグイン |
| Codex | Codexプラグイン |
| Cursor | プラグインとスキル選択規則 |
| pi | piパッケージ。追加機能は[piの案内](hooks/adapters/pi/README.md)を参照 |
| その他 | Agent Plugins。未対応ならAgent Skills |

### エージェントに依頼する

> hayashiii-ghub/hikizanのREADMEとマニフェストを確認し、現在の環境に合う方法で設定してください。既存設定と重複しないようにし、最後にスキルの検出を確認してください。

hikizan自体はインストーラーや環境別の設定状態を持ちません。利用中のエージェントが、その環境の標準的な方法で設定します。

### 手動で導入する

Claude Code：

```text
/plugin marketplace add https://github.com/hayashiii-ghub/hikizan.git
/plugin install hikizan@hikizan
```

Codex：

```bash
codex plugin marketplace add hayashiii-ghub/hikizan
codex plugin add hikizan@hikizan
```

pi：

```bash
pi install git:github.com/hayashiii-ghub/hikizan
```

Cursorはプラグイン画面からGitHubリポジトリ`hayashiii-ghub/hikizan`を追加します。その他のAgent Plugins対応クライアントでも、このリポジトリを標準の方法で追加します。

Skillsだけを使う場合：

```bash
npx skills add github:hayashiii-ghub/hikizan -g
```

導入後は新しい作業を開始し、旧版や別経路のスキルが重複していないことを確認してください。

## 対応範囲と詳細

Claude Code・Codexは起動フック、Cursorは規則ファイル、piは標準のスキル検出を使います。自然文からの選択や🌲の表示品質はモデルと実行環境に依存します。

調査・相談・設計・レビューだけの依頼では変更しません。PR提出とマージ・公開も別の依頼として扱います。

- [piの追加機能と設定](hooks/adapters/pi/README.md)：巻き戻し、画面確認、Claude委譲、Web検索
- [フックの責務](hooks/conditions.md)：環境ごとの接続、登録条件、失敗時の動作
- [開発ガイド](AGENTS.md)：編集箇所、生成・検証、配布時の確認範囲

## v2.2.0の変更

6スキルをそれぞれ1つの`SKILL.md`へ整理し、成果と判断の観点をまとめました。既存の実装・判断経緯を踏まえた再利用、改善と保守負担の比較、必要な補足だけを残す判断を明記しています。

起動時のGit状態取得・fetch、pi独自の進行ステータスと重複する選択規則の注入を削除しました。6スキルの名前と導入方法、piの短縮コマンド・ヘッダー・巻き戻し・画面確認・Claude委譲・任意のExa検索・本番操作確認は維持しています。

更新後は新しいセッションを開始してください。起動時のGit通知やpiの進行ステータスは表示されなくなります。今回の整理による使い心地の変化は、実作業で継続して確認します。
