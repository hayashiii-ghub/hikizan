# テストを先に書く場合

テスト先行は、回帰価値が高く、既存のテスト基盤から観測可能な振る舞いを安定して確認できる場合に使う。

優先する変更：

- バグ修正：同じ入力で症状を再現できる
- 業務規則・検証処理・状態遷移：入出力契約が明確
- 公開API・データ変換：利用側が依存する振る舞いがある

手順：

1. 守る振る舞いを入力と観測可能な出力で1文にする
2. 可能なら回帰テストを追加し、修正前に意図した理由で失敗することを確認する
3. 最小修正でテストを通す
4. 関連する一連のテストを実行し、既存契約を壊していないか確認する
5. 重複テストや非公開実装へ固定された検証だけ整理する

テスト基盤がない、再現が不安定、文言・スタイル・単純な設定変更などでは、無理にテスト先行へ寄せない。代わりに再現手順、静的検査、ビルド、視覚確認など、対象に合う証拠を残す。テストの有効性を証明するための追加儀式は行わない。
