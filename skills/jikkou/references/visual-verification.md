# 画面変更の確認

UI・スタイル・配置・操作を変更したら、対象プロジェクトに既存の視覚検証方法があるか確認し、その方法を使う。Shimon、Playwright、スクリーンショットテスト、Storybookなど、リポジトリで既に採用されている方法を優先する。検証のためだけに新しいツールを勝手に導入しない。

変更に関係する画面幅と状態だけを確認する。機械検査の成功だけで終えず、生成された画像や実際の表示を見て、欠け、重なり、不自然な改行、操作後の状態を確かめる。利用できる方法がなければ、視覚未確認であることを理由とともに伝える。

Shimonが設定済みの場合は、今回必要なケースだけを`.shimon/task.mjs`へ書き、対象プロジェクト所定のコマンドで実行する。JSONの`pass`と各検査を確認し、返された全スクリーンショットを`intent`と`review`に沿って見る。`visualReviewRequired: true`だけでは確認済みとしない。作業後は一時ファイルを削除する。

どの方法でも、信頼できる設定だけを実行し、スクリーンショットやログへ秘密情報・個人情報を残さない。
