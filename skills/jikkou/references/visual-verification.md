# 画面変更の確認

UI・スタイル・配置・操作を変更したら、対象プロジェクトまたは現在のハーネスで利用できる視覚検証方法を確認し、その方法を使う。shimon、Playwright、スクリーンショットテスト、Storybookなど、すでに利用できる方法を優先する。検証のためだけに新しいツールを勝手に導入しない。

変更に関係する画面幅と状態だけを確認する。機械検査の成功だけで終えず、生成された画像や実際の表示を見て、欠け、重なり、不自然な改行、操作後の状態を確かめる。利用できる方法がなければ、視覚未確認であることを理由とともに伝える。

`shimon_verify`が利用可能な場合は、起動済みの画面URLと今回必要な1〜5件のケースを直接渡す。通常は設定ファイルやタスクファイルを作らない。サーバー起動、`prepare(page)`、独自`checks`などが必要で、対象プロジェクトに信頼できるshimon設定がある場合だけ、その設定を使う。`pass`と各検査を確認し、返された全スクリーンショットを`intent`と`review`に沿って見る。`visualReviewRequired: true`だけでは確認済みとしない。

どの方法でも、信頼できる設定だけを実行し、スクリーンショットやログへ秘密情報・個人情報を残さない。
