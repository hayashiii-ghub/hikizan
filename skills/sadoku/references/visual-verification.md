# 画面変更の査読

対象プロジェクトに既存の視覚検証方法があれば、その方法で変更に関係する画面幅と状態を確認する。Shimon、Playwright、スクリーンショットテスト、Storybookなど、既に採用されている方法を優先し、レビューのためだけに新しいツールを勝手に導入しない。

自動検査の成否に加え、生成された画像や実際の表示を見て、欠け、重なり、不自然な改行、操作後の状態、アクセシビリティ上の問題を確認する。実装者の「確認済み」という説明だけを証拠にしない。利用できる方法や十分な証拠がなければ、視覚未確認として指摘する。

Shimonが設定済みの場合は、JSONの`pass`と各検査を確認し、返された全スクリーンショットを`intent`と`review`に沿って見る。`visualReviewRequired: true`だけでは確認済みとしない。

どの方法でも、信頼できる設定だけを実行し、スクリーンショットやログへ秘密情報・個人情報を残さない。
