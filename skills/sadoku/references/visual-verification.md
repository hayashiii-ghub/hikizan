# 画面変更の査読

対象プロジェクトまたは現在のハーネスで視覚検証方法を利用できる場合は、その方法で変更に関係する画面幅と状態を確認する。shimon、Playwright、スクリーンショットテスト、Storybookなど、すでに利用できる方法を優先し、レビューのためだけに新しいツールを勝手に導入しない。

自動検査の成否に加え、生成された画像や実際の表示を見て、欠け、重なり、不自然な改行、操作後の状態、アクセシビリティ上の問題を確認する。実装者の「確認済み」という説明だけを証拠にしない。利用できる方法や十分な証拠がなければ、視覚未確認として指摘する。

`shimon_verify`が利用可能な場合は、起動済みの画面URLと変更に関係する1〜5件のケースを直接渡し、`pass`と各検査を確認する。返された全スクリーンショットを`intent`と`review`に沿って見て、`visualReviewRequired: true`だけでは確認済みとしない。対象プロジェクトに信頼できるshimon設定がある場合は、高度な状態再現や独自検査にその設定を使ってよい。

どの方法でも、信頼できる設定だけを実行し、スクリーンショットやログへ秘密情報・個人情報を残さない。
