# 日本語文章規範

hikizan が出す日本語の正本で、`kaku` の文章規範。対象は PR 本文・各 skill の報告・docs。コードレビューの観点ではなく、文章の書き方を定める。

この規範は読み物 (PR / docs / 報告) の文体を前提とする。Slack など会話系に出すときは、内容の衛生 (LLM 句・冗長・平易・誠実さ) は守り、読み物向けの構造 (段落と論証・見出し) は外して短い口語にする。

出典: k16shikano gist (https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d, ライセンス Unlicense, 取得 2026-06-22)。この hikizan 版が正本。原文の更新は手動で取り込む。

書いたら、各節の点検項目を上から当てる。直すのは規範に外れた箇所だけ。

## 整形

- 一文ごとに改行する。段落の区切りは空行で示す。
- コード・差分・ログ・設定の断片はコードブロックに入れる。
- 本筋から一段外れる補足 (用語の由来・定式化の名称) は脚注 (`[^ラベル]`) に降ろす。
- 初出で定義・導入する用語は太字。すでに導入した語を話題として指すとき・引用・通称は「」(初出は太字、以後は「」)。
- ダッシュ (em `—`、horizontal bar `―`、2倍ダッシュ「——」) を地の文・見出しで使わない。挿入は括弧 ()、言い換えは句点で二文に分けるか読点でつなぐ。範囲の en ダッシュ `–`・英語複合語 (`Curry–Howard`)・コードブロック・書誌は対象外。
- 中黒 (・) を並列で使わない。単一の固有名詞の内部は可。例外として、hikizan 自身の docs は並列中黒を表記として維持する (#48 の決定)。PR 本文と報告には原則どおり適用する。
- 見出しに区切り線で「種別──主題」と二要素を詰めない。単一の自然な句にする。
- 用語と定義を並べる箇条書きは全角コロンで「**用語**：説明」と書く。

## 段落と論証の構成

パラグラフライティングを基本にする。読者が段落単位で論理を追える状態にする。

- 一段落に一トピック。場面 (調査・報告・検証・評価) が混ざる長い段落は分割する。
- 段落の最初の文を読めば、その段落が何の話か分かるようにする。
- 段落の先頭で前段落との論理関係を接続表現で示す (「であれば」「実際」「しかし」)。
- 論証は一方向に進める。結論→反論→結論の言い直しにしない。反論と疑念を処理し終えてから、結論を一度だけ置く。
- 誤った解釈は明示的に否定してから本当の理由を述べる (「その理由は『〜だから』ではない。〜だからだ」)。
- 「AではなくB」と否定するときは根拠を一文添える。反実仮想 (「もしAなら〜だっただろう」) が使えることが多い。
- 譲歩 (「確かに〜」) は事実確認にとどめる。あとで訂正する内容を著者の声で断定して自己矛盾を作らない。通説の声に帰属させる (「〜と要約できてしまうかもしれない」)。
- 山場で効かせたい情報 (数値・固有の事実) を手前の段落で先出ししない。
- 否定・限定するときは、否定する命題そのものを「」で正確に書き出す。漠然とした否定で済ませない。
- 前方参照 (「後の章で扱う」) は論証が一段落した位置 (段落末・節末) に置く。途中に挟んで流れを切らない。

## 論証の厳密さ

書き上げたら、読み手の反論を先回りして点検する。

- 推量・可能性・読者の疑念・反実仮想の文を、機械的に断定へ変えない。根拠なく主張を弱めている場合だけ「かもしれない」「だろう」を削る。確定しているときだけ断定に直す。
- 区別すべき対象 (別々の決定・別々の原因・種類の違う問題) を一括りにしない。腑分けする。
- 複数の要因がある事象を単一の原因に還元しない。例が複数種類の問題を含むなら切り分けて対応づける。
- 章・節をまたいで同じ概念の扱いを一致させる。分類・定義・用語の地位を全体で揃える。
- 因果を主張するときは、その機構 (なぜそうなるのか) を一文で示す。「AだとBになる」だけで理由を省略しない。
- 検出・保証・解決を「必ず」できるかのように書かない。条件付きで述べる (「〜しやすい」「〜が成り立つときに限り」)。
- 挙げた例が主張の全体を支えているか確認する。一部しか支えないなら主張の範囲を狭める。
- 「次節で扱う」と逃がした論点は本当に回収する。回収しない伏線を張らない。
- 譲歩・限定 (「ただし」「とはいえ」) を置いたら、その後で論を進める。逆接で終えて宙吊りにしない。
- 節の中心となる語は、使う前に定義・対象範囲を述べる。

## 読み手の負荷の管理

読者の記憶と注意を有限の資源として扱う。

- 後で参照しない固有名 (ファイル名・関数名・識別子) を出さない。一般的な言い方で済ませる。
- 抽象的な言い回しの指す内容が一意に決まらないときは、丸括弧の同格挿入でその場で特定する。読者に前を読み返させない。
- 新しい例で読者が保持する文脈が増えるときは、前の例と何が違うか・なぜもう一つ必要かを前置きする。
- 章冒頭・節導入に、これから扱う内容に関係しない過剰な詳細を詰め込まない。
- 議論に必要な具体は残す。省くのは装飾的精度 (時刻・HTTP ステータス・カバレッジ率) や後で参照しない固有名。

## 視点と語り

- 例示は受動態の羅列ではなく、行為者を主語にした動作の連なりで書く。
- 架空の人物設定 (「入社2年目のエンジニアが」) を無意味に冠しない。
- 論証の中で読者を「あなた」と呼ばない。役割名 (「開発者」「読者」) で書く。二人称は導入や結びの要所にとどめる。
- 対象を指す語は具体的に選ぶ。「AI」「ツール」のような広い語でぼかさない。
- 導入した術語は以後その語で通す。「文脈」「ツール」のような曖昧語に後退しない。
- 術語・訳語はその分野の慣用語を選ぶ。意味の近い漢語を一般語の感覚で充てない。
- 術語の響きを持つ語を、術語でない場面に流用しない。普通の言い方で書く。

## 演出の抑制

全面禁止ではなく節度の規範。修辞は効果を生む箇所でだけ使う。

- 溜め・修辞疑問で導出を演出するのは要所に限る。説明で足りる箇所はそのまま述べる。
- 短い決め台詞を独立段落にする演出を多用しない。体言止めは山場に限る。
- 本文中の太字強調を多用しない。論理の要所に限り一節に一、二箇所まで。それ以外は順序と構造で際立たせる。
- 「〜してはならない」より「〜するわけにはいかない」のような作業者の判断として書く形を選ぶ。
- 転回点を過剰に劇的にしない。事実を述べる一文で足りる場合が多い。
- 帰結の列挙で事故や危険を煽らない。
- 「重要なのは〜である」で主張を予告しない。主張をそのまま書く。
- 「AではなくBだった」の対句の決め台詞を多用しない。
- ひねった言い回し・一意に決まらない比喩を使わない。平易な動詞でそのまま言う。

## LLM っぽい表現の禁止

中身のない型に誘惑されない。書き上げたらこの節で点検する。次の言い回しは論点を増やさず「ちゃんと書いている感」だけを付ける。使わない。

- 予告と総括: 「重要なのは〜である」「本章では〜を扱う/探求する」「ここでは〜について見ていく」「まとめると」「要するに」(直前の言い換えだけのとき)、「〜に他ならない」
- 正面から系: 「正面から扱う/回収する/見る」(中身の代わりに姿勢だけを宣言する)
- 空虚な形容: 「不可欠」「核心的」「鍵となる」「根本的な」「多角的」「包括的」「総合的」
- 空虚な動詞: 「掘り下げる」「深掘りする」「言語化する」「触れる」「言及する」
- 接続の型: 「〜において」「〜という側面から」「〜の観点から」(新情報なし)、「さらに」「また」「加えて」の連打
- 弱い緩和と称賛: 「〜と言えるだろう」(根拠なく弱める場合だけ)、「非常に」「極めて」「大いに」

本書の術語を議論に使うのはよい。空虚な装飾として使うのが問題。

## 冗長の排除

無駄な文章をなるべく残さない。

- 同じ主張を言い換えて繰り返さない。一つの主張は一度だけ書く。
- 隣接する節が同じことを別角度で述べているなら、片方に吸収して一つにまとめる。
- 場面の描写の直後にその内容を要約し直さない。意味づけの一文だけを置く。
- 同じ論理的役割の並列の事実は、文を分けて重ねず一文にまとめる。地位は文頭の語で示す。
- 読者が自力で補える中間段階の説明は書かない。
- 数文の議論を一文に圧縮できるなら、圧縮した一文だけを残す。
- 接続や評価のためだけの文 (「それ自体はよいことである」) を置かない。
- 想像上の読者との問答を修辞として使わない。主張はそのまま述べる。
- 著者の立場の弁明や断り (「本書もそれを否定しない」) を書かない。事実の記述だけを置く。
- 本文でまだ導入していない概念や文書名を先回りして持ち出さない。
- ためらいのある弱い述語で済ませない。本文内の根拠で確定していることは強く具体的に言い切る。ただし不確実性・可能性・仮定を表す弱い述語は保持する。

## 読者への誠実さ

- 例が作為的に見えうるなら隠さない。読者の疑念を先回りして認め、現実にあり得る根拠を短く添える。
- その根拠は著者の断定ではなく、読者自身の経験に訴える一般的事実や通説に求める。
- 確認していないことを、確認したかのように滑らかに書かない。

## 見出しの付け方

見出しは内容を特定できる具体的な句にする。その節が答える問い、または扱う対象を指す。

- 作業の手順だけを述べる見出しや、情報量のない見出しにしない。
- 見出しを節の結論を言い切る「セリフ」にしない。見出しの時点でオチを知る状態を避ける。
- 節で扱う対象を指す名詞句でもよい。
- 疑問形か断定形かは問わない。問うのは、扱う対象や読者の持つ問いを指しているか。本文のトーンに合うほうを選ぶ。
