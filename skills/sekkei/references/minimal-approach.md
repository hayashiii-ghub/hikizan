# 最小案の選び方

要求を満たす最小案を選ぶため、次の順に確認する。

ここでいう最小とは、変更範囲、工程、成果物を要求に必要な分へ絞ることであり、文章を短く切り詰めることではない。読み手の判断に必要な説明、用語の意味、理由と結果のつながりは残す。

1. その問題は本当に解く必要があるか
2. 既存実装がなかった場合も同じ構成を選ぶか
3. プラットフォーム標準または既存の依存関係・パターンで解けるか
4. 判断、決定論的処理、安全制御のどの層へ置くべきか
5. 新しい層・設定・文書を増やさず局所変更で解けるか
6. 要求外の整理や将来拡張を別の対象範囲へ出せるか

削ってはいけないもの:

- 信頼境界の検証
- データ損失と失敗時の後始末への対処
- データ、非同期処理、外部資産、削除、認証を含む計画では、整合性、競合、再試行、ライフサイクル、入力・権限境界に抜けがないか確認する
- セキュリティとプライバシー
- アクセシビリティ
- 問題を再現するために必要な検証

計画には、採用案、主な変更、検証、意図的に見送る対象範囲だけを残す。行数見積りや点数評価のために計画を膨らませない。
